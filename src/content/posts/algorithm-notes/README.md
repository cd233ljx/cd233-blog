# 算法分析与设计

- `articles/`：MDX 正文；`series` 指定归属，`order` 指定阅读顺序，`slug` 保持文章地址稳定。
- `components/`：本系列的演示、计算模型和局部样式。正文从 `../components/` 导入。
- `assets/`：本系列使用的图片等素材。
- `notes/`：写作备忘，不作为文章读取。
- `series.json`：系列标题与简介；篇目清单从文章生成。

运行 `npm run dev:background`，打开 `/series/algorithm-notes/` 管理草稿并预览。正文和组件保存后使用同一个开发服务更新。

新建章节：`npm run new:post -- algo-new "文章标题" --series algorithm-notes`。默认安排在最后，也可显式传 `--order`。

AI 先读取最新正文及相关演示，只修改指定范围。人工开始修订后保留人工措辞；事实或课件来源不确定时标记待核对。文章正文不提交 Git，交接保留私有备份；组件与配置使用 Git 留版本。发布前运行 `npm run verify`。

文章不附加“自测”问答块，跳转链接不使用箭头标识。

## 演示维护

- `common.tsx` 统一实验卡片、Radix Slider 进度条、播放速度、图例和伪代码；图标来自 Lucide React。保留键盘操作、减弱动效和切页清理。
- `charts.tsx` 使用 Recharts 绘制增长比较与作业时间轴，按需加载；图表旁保留可读的数据表或起止时间。增长图使用 `log₂(次数 + 1)`，不能把条长解释成实际耗时。
- `*-model.ts` 保留纯计算与过程快照，`models.test.ts` 用独立枚举、输出重建及不变式校验正文算例。展示层不要另写一份算法答案。
- 正文的复杂度描述算法本身，不包括交互演示保存全部快照的额外空间。改变输入时重建播放器，避免旧进度对应新数据。
- 新增解释使用可核对的算例；原稿的课件页码保留，正式发布前仍需对照原课件核实。
