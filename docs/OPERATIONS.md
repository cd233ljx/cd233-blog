# 部署与运维

## 发布模型

本站前台是 Astro 静态站点，写作服务负责认证、内容保存与静态版本发布，正式地址为 `https://blog.utopiacd.online`。

仓库只维护源码与公开的构建约定；域名解析、网络入口、服务器路径、容器编排、访问凭据和内部排障命令均由部署环境单独管理，不进入公共仓库。

## 发布构建

发布文章或代码改动前运行：

```bash
npm run verify
```

该命令会依次完成类型检查、测试、格式检查、静态构建与 Pagefind 搜索索引生成。只有命令成功结束，才应将当前版本视为可发布版本。

构建结果位于 `dist/`，不提交 Git。具体上线动作由服务器侧配置完成，与仓库源码保持解耦。

## 版本管理

发布前检查工作区，确保线上内容有对应的 Git 记录：

```bash
git status --short --branch
npm run verify
```

提交时只暂存本次确认过的文件，不要把构建结果、缓存、环境变量或本机运维配置加入仓库。

`git push` 表示源码已经同步到远端，不等同于生产环境已经完成构建或上线；最终状态应以正式站点验证结果为准。

## 发布验证

上线后至少检查：

```bash
curl -I -A 'Mozilla/5.0' https://blog.utopiacd.online/
```

- 首页和已发布文章返回 `200`。
- 不存在的地址返回 `404`。
- canonical、Sitemap 与页面中的正式域名一致。
- 页面排版、图片、主题切换和搜索功能正常。

## 安全边界

公共仓库中不得记录或提交：

- 家庭网络结构、内网地址、监听端口和设备信息。
- 服务器绝对路径、容器名称、挂载关系和内部服务拓扑。
- Tunnel 标识、DNS 管理细节、防火墙规则和管理后台地址。
- Token、API Key、证书私钥、环境文件及任何访问凭据。
- 可直接复现生产环境控制面的完整运维命令。

公开文档只说明项目自身的构建与发布契约。需要记录服务器操作时，应存放在服务器本地的非公开运维文档中。

## 回滚原则

回滚时从 Git 中选择已确认的源码版本，重新执行完整验证与构建。工作区存在未提交内容时，先保存需要保留的修改，不要使用可能丢失内容的强制重置命令。

## 后台运行契约

生产反向代理将本站请求交给常驻 Node 服务，服务提供当前发布版本的静态内容及后台接口。不要直接暴露源码、环境文件或私有数据目录。反向代理和进程守护配置由部署环境维护，账号密码摘要同样只存在本机环境文件中。

首次启动使用已验证的 `dist/`；后续后台发布使用私有版本目录和持久化版本指针。构建失败不切换网站，后台展示错误日志。服务重启后恢复最后一次发布的版本，但要求重新登录。

备份应包含文章、`src/config/site-content.json`、两份上传图片目录、私有历史与回收目录、`media.json` 图片描述和 `manifests/` 发布快照。旧 `previews/` 构建目录与 `live-preview/` 开发缓存不作为备份。实时预览使用回环开发服务，页面和热更新连接统一经后台会话认证；反向代理需支持 WebSocket Upgrade。保留旧版本用于回滚；维护者可停用服务后恢复已知有效的版本指针，再启动并验证页面与搜索。不要整份覆盖后来修改的反向代理配置。后台不会自动提交或推送 Git；文章与上传图片需要按版本管理流程归档。
