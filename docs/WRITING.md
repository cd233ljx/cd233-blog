# 写作与发布

文章统一保存在 `src/content/posts/`。独立文章直接放在根目录，系列文章放在 `<系列标识>/articles/`。固定 `slug` 决定文章地址，整理目录时保留它；旧的独立文章未填写 `slug` 时沿用文件名：

```text
src/content/posts/astro-content-collections.md
→ /posts/astro-content-collections/
```

## 创建草稿

推荐使用脚手架命令：

```bash
npm run new:post -- astro-content-collections "用 Astro 内容集合管理文章"
```

它会创建一篇 `draft: true` 的 Markdown 草稿，并拒绝覆盖同名文件。

## 在 IDE 中管理系列

一个博客仓库共用一套依赖、主题和开发服务。每个系列有自己的正文、专用组件和素材：

```text
src/content/posts/
  独立文章.md
  algorithm-notes/
    series.json          # 系列标题、简介
    articles/            # Markdown / MDX 正文
    components/          # 专用交互、计算模型和样式
    assets/              # 本系列的图片等素材
    notes/               # 写作素材和备忘
    README.md            # 写作说明
```

只读取根目录文章和 `*/articles/*.{md,mdx}`；`README.md`、`notes/` 与组件说明不会被当作文章，也不会原样复制到公开站点。它们仍在 Git 仓库中，不要存放私密信息。跨系列复用的组件继续放在 `src/components/`。

```bash
npm run new:series -- blog-building "搭建个人博客"
npm run new:post -- first-step "从第一步开始" --series blog-building
```

新系列会生成目录、简介和写作说明。系列文章默认使用 MDX、保持草稿，顺序默认接在已有章节最后；也可传 `--order 0` 创建导读，或用其他未占用的非负整数。重名文件、固定地址和重复章节顺序会被拒绝；所有系列的文章文件名保持唯一，后台才能沿用同一份历史记录。

系列文章增加以下信息：

```yaml
slug: algo-13-knapsack
series: algorithm-notes
order: 13
draft: true
```

`series.json` 只保存标题和简介，不再手写一份篇目清单。系列与标签并存：系列规定连续阅读的顺序，标签仍可跨系列检索；全部文章和归档继续按日期排列。

运行 `npm run dev:background`，打开 `/series/`。本地系列页包含草稿，点击篇目标题预览正文；在 IDE 中打开对应系列的 articles 目录编辑。页面不展示源码路径、终端命令和写作说明。正文或组件保存后，使用同一个开发服务更新预览。开发服务监听局域网地址，能访问该服务的人也能看到草稿。正式构建隐藏写作工具和路径，只生成含公开文章的系列，目录及前后篇导航自动跳过草稿和未来日期文章。

AI 起草前先读取系列 README、最新正文和相关组件；默认保持 `draft: true`。人工修订后，以最新文件为基础，只修改指定范围，保留作者措辞，不编造经历和课件来源。初稿、人工定稿交接时用 Git 留版本。直接在 IDE 或由 AI 修改文件，不会触发后台的历史备份。发布前核对正文、公式和演示使用的输入与结论是否一致，再运行完整验证。

也可以手工创建 `.md` 或 `.mdx` 文件：

```md
---
title: '文章标题'
description: '用于列表卡片和 SEO 的一句摘要。'
publishedAt: 2026-08-09
updatedAt: 2026-08-10
tags:
  - Astro
  - 内容管理
featured: false
draft: true
---

这里开始写正文。
```

## Frontmatter 字段

| 字段          | 必填     | 说明                                     |
| ------------- | -------- | ---------------------------------------- |
| `title`       | 是       | 文章标题，最多 120 个字符                |
| `description` | 是       | 卡片与页面摘要，最多 240 个字符          |
| `publishedAt` | 是       | 发布时间，使用 `YYYY-MM-DD`              |
| `updatedAt`   | 否       | 内容有实质更新时填写                     |
| `slug`        | 新稿建议 | 固定文章地址；搬目录时保持不变，不能重复 |
| `series`      | 否       | 对应系列目录的标识，与 `order` 一起填写  |
| `order`       | 有系列时 | 非负整数，0 可用于导读，同系列内不能重复 |
| `tags`        | 否       | 最多 12 个；重复标签会自动去重           |
| `featured`    | 否       | 首页最近文章中优先排列置顶文章           |
| `draft`       | 否       | 开发环境可见，生产构建会排除             |
| `cover`       | 否       | 相对于文章文件的本地图片路径             |
| `coverAlt`    | 有封面时 | 封面替代文本，使用封面时必须填写         |

未来日期的文章也不会进入生产构建。标签、归档与相关文章都由内容集合自动生成。

## 封面与正文图片

建议把图片放在 `src/assets/posts/<slug>/`，由 Astro 处理尺寸和格式。文章在 `src/content/posts/` 时，封面写法如下：

```yaml
cover: ../../assets/posts/astro-content-collections/cover.webp
coverAlt: 'Astro 内容集合的数据流示意图'
```

普通 Markdown 图片仍可使用标准语法。需要响应式图库时使用 MDX 的 `Gallery` 组件。

系列图片可放在同系列的 `assets/`，例如封面使用 `../assets/cover.webp`。系列文章引用公共 `src/assets/posts/` 时，路径是 `../../../../assets/posts/...`；后台媒体库保存时会自动换算。

## MDX 组件

将扩展名改为 `.mdx` 后，可以直接使用以下受控组件：

```mdx
<Callout type="tip" title="提示">
  提示内容。
</Callout>

<LinkCard
  href="https://docs.astro.build/"
  title="Astro 文档"
  description="框架的官方使用文档。"
/>

<Mermaid
  title="内容流"
  chart={`flowchart LR
    A[Markdown] --> B[Content Collection]
    B --> C[Static Page]`}
/>

<VideoEmbed provider="bilibili" id="BV..." title="视频标题" />

<AudioPlayer src="/audio/example.mp3" title="音频标题" />
```

`Callout` 的 `type` 支持 `note`、`tip`、`warning`、`danger`；视频支持 `youtube` 与 `bilibili`。完整接口以 `src/components/content/` 中的组件 Props 为准。

### 交互算法笔记

算法复习笔记位于 `src/content/posts/algorithm-notes/`。当前仅保留 `articles/algo-01-complexity.mdx`，内容为《第一章 算法引论｜第二轮复习》，保持草稿及原有 `/posts/algo-01-complexity/` 地址。本地从 `/series/algorithm-notes/` 编写和预览。

演示组件放在同系列的 `components/`，由文章显式导入，例如：

```mdx
import { LCSDemo } from '../components/Dynamic';

<LCSDemo client:visible />
```

保持 `client:visible` 才会在进入视口后启用交互。含导入、公式和交互组件的文章使用 Markdown 编辑；旁边的本地阅读预览直接显示公式；交互演示区显示最近同步版本的可操作组件。正文与配套组件需要一起保留，不能只迁移 MDX。

演示共用带速度选择的单步播放器，进度条支持键盘方向键与 Home / End。状态表使用边框、下划线和加粗区分当前计算、读取来源与选中路径，空白状态以 `·` 显示。增长图和作业时间轴旁保留数值说明；正文的时间、空间复杂度不包含演示快照的开销。

系列目录和篇末链接自动生成，分批发布无需手工移除尚未公开章节的链接。修改算法时同步检查对应的计算模型与演示，不把硬编码结果当作算法输出。

## 发布检查

1. 摘要能独立说明文章内容。
2. 日期和标签正确。
3. 所有图片都有有意义的替代文本。
4. 将 `draft` 改为 `false`。
5. 运行 `npm run verify`。

验证通过后，静态页面、Sitemap 和 Pagefind 索引会在构建时一起更新。Git 提交、上线确认与公开文档的安全边界见 [部署与运维](OPERATIONS.md)。

## 在写作后台编辑

登录后先看到文章列表，可按草稿、已上线或待发布筛选，搜索标题、标签与摘要。新文章默认是草稿，填入标题并停顿输入后自动保存；顶部状态会显示保存进度。Ctrl / ⌘ + S 立即保存。摘要留空时从正文生成，也可以在「文章设置」里手动填写。

文章默认使用「分栏」：左侧编辑 Markdown / MDX，右侧在浏览器即时渲染正文和公式，交互演示区显示最近同步版本的动画。可切换「编辑」或「阅读」；窄屏分栏上下排列。文本、公式、导入与 JSX 都保留在原文件，不经过可视化卡片转换。组件由 Codex 或其他仓库工具维护，无需在后台注册属性表单。

封面、标签、日期、摘要、置顶与固定地址放在右侧设置栏。新文章使用 MDX，首次保存前可以修改地址与文件格式；保存后地址固定。正文支持行号、语法高亮与撤销，用 Markdown 图片语法引用图片。

### 保存、预览与发布

- **自动保存 / 保存**：写入源文件，不改变线上页面。多窗口修订冲突会暂停自动保存，不覆盖另一窗口的内容。
- **阅读预览**：普通正文和公式在浏览器即时更新，未保存或同步失败时也可预览。只有交互演示需要首次连接编译服务，后续复用缓存并在同步后更新，不构建整个网站。顶部「预览」可以放大并切换桌面、手机尺寸。预览包含草稿，仅登录后可见。
- **发布…**：先保存，再显示确认清单。确认后把当前文章标记为公开，并发布全部已保存的公开文章与站点修改。
- **发布中心**：比较源文件和线上版本，列出待发布、更新、下线与删除的内容。源码中标记公开不等于已经上线。
- **转为草稿并下线…**：确认后保存草稿状态并构建网站。构建失败仍保留线上原版。
- **删除文章…**：移入私有回收目录。下次发布网站时才会移除线上页面，图片不会连带删除。

未来日期的文章不会进入正式构建，到期后仍需再次发布网站；当前不提供自动定时发布。置顶只影响首页最近文章顺序。

### 图片与历史

图片通过媒体库上传后，用 Markdown 图片语法写入正文，也可以填写图片地址。媒体库支持搜索、缩略图、显示名称、替代文本与重复使用，封面和站点图片共用媒体库。图片最大 10 MB，支持 PNG、JPEG、WebP、GIF 与 AVIF，上传后转换为 WebP，动图取静态帧。正文使用 `/uploads/`，封面使用本地资源引用。

在文章设置中打开「查看历史版本」，可以对照历史与当前正文，恢复任一列出的旧版本；当前版本会先备份。恢复不自动发布。后台每篇文章列出最近 100 个历史版本，其他历史仍保留在私有目录。删除文章的恢复由维护者处理。

未保存的文章输入会异步保留在 IndexedDB 中，按标签页隔离；在同一标签页刷新或重新打开文章可选择恢复。它不代替服务端保存。网络或修订冲突时，保留正文后重新打开服务器版本，避免直接覆盖他人的修改。

### 编辑文章以外的内容

「页面与站点」包含首页、关于页、站点资料与图标、默认分享图片、导航、页脚及各页面文案。长内容使用同一套可视化 / Markdown 编辑器，导航与页脚链接可以增删排序。切换内容分区保留当前输入；「保存内容」写入配置，「预览页面」先保存并打开实时页面预览，发布中心统一发布。

数量文案支持 `{count}`，阅读时长支持 `{minutes}`，更新日期支持 `{date}`，标签详情支持 `{tag}`，版权支持 `{year}` 与 `{author}`。动态数据由文章和当前日期计算，编辑的是显示格式。正式域名与后台认证配置仍由维护者管理。

## 后台系列管理与 AI 协作

后台导航的「系列」支持创建系列、修改名称和简介、添加已有文章、移出系列、上下移动篇目，以及在选定系列中新增草稿。先点击「保存系列」，再打开文章编辑正文；已有篇目时可点击「预览系列」查看实际目录和文章。系列标识创建后固定，名称可改。

新增文章写入所选系列的 articles 目录。给已有文章更换系列只修改 frontmatter 的 series 和 order，不搬文件，保留已有组件、图片的相对引用和固定文章地址；移出系列不会删除文章。排序保存后按显示顺序重新编号为 0、1、2……。保存冲突时先重新读取，避免覆盖另一窗口或 AI 的修改。

日常分工：AI 在仓库生成草稿和可视化组件，你在后台修改正文、管理系列，最后预览并发布。AI 后续修改组件前须读取最新文件，保留你的文字。文章中的导入、公式和组件保留原文，真实演示直接在阅读窗运行。仓库中的组件修改会热更新预览；返回窗口时会检查仓库修订并同步正文。存在未保存输入时会暂停自动保存并提示冲突，不覆盖任一方的修改；可先复制当前输入，再载入仓库版本。

系列名称、简介和篇目修改保存后不会自动上线，统一通过发布中心发布。名称和简介修改单独列入待发布清单；公开篇目的调整计入相应文章变更。

## 粘贴对话内容

文章正文支持 GFM 表格、任务列表、删除线、嵌套列表、引用、链接、图片、代码块和行内代码。保留博客正文样式，后台阅读预览与文章页共用排版。

公式支持 `$...$`、`$$...$$`，以及粘贴文本中的 `\(...\)`、`\[...\]`。后两种在解析前转换为数学节点，源文件保持原文；代码示例、已有美元公式和 HTML 块不转换。公式内部使用 KaTeX 支持的 TeX 命令，生成器与样式包保持同一版本系列。原始 HTML、MDX 组件和 ChatGPT 专有卡片不属于普通 Markdown 兼容范围；普通文本中的 JSX 特殊字符仍需转义或放入代码。
