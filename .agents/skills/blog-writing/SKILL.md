# 博客写作与交互笔记

正文和组件以仓库文件为唯一来源。AI 在仓库写文章、实现演示；作者可以在后台用 Markdown 修改文字，在阅读窗直接操作动画。组件通过 MDX 导入，不需要作者手工改代码或在后台配置组件表单。

下文命令和代码路径以仓库根目录为准。字段、目录和功能细节以当前仓库文档为准，按任务读取，不复制另一套写作规范。

## 接手一篇文章

- 先读 [写作约定](../../../docs/WRITING.md)，查看工作区改动，再读取目标文章的最新文件。属于系列时，还要读该系列的 `README.md`、`series.json` 和相关篇目；涉及演示时读取实际导入的组件及模型。
- 新会话以当前文件为准。后台人工编辑和仓库 AI 修改会落在同一份正文上，保留作者已有措辞，只修改请求范围，不拿旧聊天中的稿件覆盖最新内容。
- 优先从用户给出的资料、现稿和系列说明补齐上下文；主题、目标文章、关键事实或修改范围仍不明确时先问用户。不编造个人经历、课件出处或未经核对的结论。
- 系列自己的规则只作用于该系列；算法笔记不是所有新主题的固定模板。仅请求提纲或评审时，交付对应结果。

## 新建或改写

新稿优先使用已有脚手架，按需选择命令：

```bash
npm run new:post -- <slug> "文章标题"
npm run new:post -- <slug> "文章标题" --series <series-id>
npm run new:series -- <series-id> "系列标题"
```

- 独立文章放在 `src/content/posts/`，系列文章放在 `src/content/posts/<series-id>/articles/`。脚手架会检查地址重名和章节顺序；系列的 `order` 默认接在末尾，指定章节位置时才传 `--order`。
- 独立稿默认生成 `.md`，系列稿默认生成 `.mdx`。需要导入交互组件时使用 `.mdx`；补齐标题、摘要、正文和实际需要的元数据，清除脚手架占位内容。
- 新文章保留 `draft: true`。修改已有文章时保留其发布状态和 `slug`；整理系列不应改变旧文章地址或破坏图片、组件的相对引用。
- 阅读路径由文章 `slug` 决定，不等于系列目录或当前文件名。文章文件名还用作后台标识，跨系列保持唯一；不要随手重命名已有文章。
- 写作契约发生变化时同步更新 `docs/WRITING.md`；普通文章修改沿用现有契约。

## 需要交互内容时

先读 [开发约定](../../../docs/DEVELOPMENT.md) 和 [设计约定](../../../docs/DESIGN.md) 中相关部分。改变内容加载、路由或布局时再读 [架构说明](../../../docs/ARCHITECTURE.md)。

- 系列专用组件、模型和样式放在该系列的 `components/`，图片放在 `assets/`；跨文章复用的组件放在 `src/components/`。优先复用已有实现，不为普通文字修改重建演示。
- 在文章中显式导入组件，按交互需要保留或选择 Astro 的 hydration 指令；本站演示通常使用 `client:visible`。只输出静态 HTML 的组件不会因此自动具有交互。
- 正文中的公式、例子、输入和演示结论应一致。修改计算逻辑时检查对应模型及已有测试，不用固定展示结果冒充实际计算。
- 作者在阅读窗操作真实组件；不要把源码占位卡片、组件属性表单或“让作者粘贴代码到后台”当作交付结果。除非任务本身要求，不扩展后台编辑器来适配文章组件。

## 预览与验证

后台采用 Markdown 编辑、分栏和阅读视图。保存正文后预览更新；仓库中的组件修改通过热更新显示，正文修改也会同步到编辑区。有未保存输入时后台会保留输入并提示冲突，不要求作者放弃修改来强制同步。

- 确认修改的是浏览器预览所读取的仓库检出目录。另一份 worktree 的修改不会自动进入当前预览；若两者不同，先核对目标。
- 复用已有单篇预览。需要本地开发服务时先运行 `npm run dev:status`，未启动再用 `npm run dev:background`；从 `/posts/<slug>/` 或对应系列页面打开文章。后台私有预览及进程管理见开发文档。
- 编辑过程中使用按需预览。整站构建用于完成修改后的质量验证，不作为每次查看文章的步骤，也不为预览文章执行发布或重启后台。
- 改了交互时，在浏览器中实际操作相关按钮、输入或播放控件，检查状态变化；涉及布局时检查窄屏和深色模式。仅确认返回 HTML 或截到静态画面不足以证明交互可用。
- 按改动运行相关已有测试，交付仓库修改前运行 `npm run verify`。如浏览器或检查环境不可用，明确说明未验证的部分。

交付时给出文章文件、固定阅读路径、草稿或公开状态，以及已验证的结果和未完成事项，便于下一会话从文件继续。

## 用户要求上线时

保存、预览和公开发布是不同操作。写作任务默认完成仓库内容和预览验证；用户明确要求公开发布或部署当前改动时，读取 [运维约定](../../../docs/OPERATIONS.md)，按已有授权推进，不重复索要同一授权。

结合上下文判断“生效”指预览更新、文章公开发布还是后台程序部署；目标不明时先确认。发布前检查实际变更清单：后台发布会包含所有已保存的公开文章与站点修改，不能把一次单篇请求扩展成无关内容上线。部署命令、服务路径和凭据遵循本机非公开配置，不写入此技能。
